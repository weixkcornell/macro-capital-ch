# v2.9.0 现状 / Status

## 能用的 / Works

- **完整的判断流程，不是结论清单。** 十五层能力框架（第 0 层是基准与目标函数的总开关）、
  六步内化流程、主动收益的基本成分三分解（① 支付收益率 ② 现金流增长 ③ 估值回归，
  ③ 的「含／不含」两版并列强制），以及每条口径配的失效条款。
- **三道横切闸门，任何一道不过就不发布。** 闸门 A 统计可信（七条）、闸门 B 实施成本与
  可执行（六条）、闸门 C 数据质量与规则版本（四条）。闸门 C 补的是前两道默认成立、
  实测会破的那两件事：输入数据是否对、规则是否稳定。
- **两个可跑的任务 DAG。** 「A股观点看板」与「周期定位与配置研判」，各带组队模板、
  槽位、产物落点与版式契约（`designSystem` 的 tokens/组件/指令，**未声明的指令 fail-closed**）。
- **数字一致性是可执行的，不靠自觉。** 摘要、正文、底座三方对撞
  （`i1_collision_check.py`）；报告生成器自带空值自检，注入失败产生的 `None/nan/inf`
  直接让生成失败，而不是让「数字一致性门禁只核对数字、抓不到 None」这种缺口漏进正文。
- **取数优先级被写成规则并可机检。** Wind CLI 第 1 档，westock CLI → 公开接口自算 →
  外部口径（须标来源与 as-of）依次退回；**当期实际落在哪一档必须声明**。
  凭据缺失 fail-closed，禁重装/绕走，降级须逐项标注（`check-wind-provenance.py`，6/6 自校准）。
- **移动端可读性与溢出是可测的。** 320/375/390 三档，读 computed style 而非声明值；
  六档视口溢出 + WCAG AA 对比度（`audit-render.py` / `audit-mobile.py`，7/7 自校准）。
- **文风渲染是末位工序。** 事实层（数字／口径与数据期／结论方向／脚注）冻结，
  只改表达；出 `style-report.json`（8 条逐条结果 + 反例命中数须 0 + 刊名出现次数须 0），
  缺报告视同未渲染。
- **发布前十件套可复跑，全绿才发布。** 包自检、门禁负向对照（52 例）、digest 可复现性、
  i1 解析层自检、冒烟测试、文档-契约一致性、模板一致性自校准、移动端与 Wind 自校准、
  门禁接线检查、仓库骨架自检。CI 每次 push 与 PR 都跑，并在 Linux 与 Windows 两个平台各跑一遍（行尾纪律要跨平台验）。
- **判据登记表是生成的，不是手写的。** `CRITERIA.md` 由代码里的判据表逐字生成并比对，
  登记 23 条判据，每条写明「查什么／不查什么／能报什么 code」；
  覆盖率报表显示 51 个文件里 50 个有针对性判据、0 个没人读。
- **可复现的 digest。** `sha256(SKILL.md)` 与 `sha256(source/SOURCE-MANIFEST.json)`，
  两者都声明 `digestTarget`；`.gitattributes` 钉 `eol=lf` 使行尾不因平台漂移。
- **源账本与禁例表强制同步。** 51 源逐条登记（`distributable: false`），
  题名与作者词干进禁例表，strict 缺口与待判定数都必须为 0。
- **本地 skill 侧同步。** 包内 `skills/macro-capital-framework/SKILL.md` 与本地
  `macro-capital-market-analysis` 技能同版本发布，改一处即两处。

## 还没有的 / Not yet

- **⑭⑮ 两层的底本实证全是海外样本**（美国宏观、G10 货币、国际油价、美股标的）。
  机制通用，但参数必须本地重标定——A 股涨跌停、T+1、停牌结构性改变波动率持续性，
  **禁止直接沿用海外 GARCH 参数**。
- **A 股本地没有对应的模型竞赛基准表。** 引用模型相对表现时必须标「未获取本地基准」。
- **A 股宏观数据修订史（vintage）未获取。** 实时数据流纪律在本地只能作原则要求，
  无法做真正的回溯复现。
- **闸门 C 的部分判据只能人工核。** 包里没有独立执行器去查「数据有没有断点」，
  它声明为 semantic 并附理由——不假装是可执行硬门。质检三件套目前靠
  `data_qc_out.json` 这类产物侧证据自证。
- **命中率的样本还太短。** 技能 vs 运气的二项检验要求 ≥10 年样本，
  目前远未到，所以累计命中率一律须附无条件基准率与恒定基准，
  且跨 `skill_version` 必须分组呈现。
- **Wind CLI 在本机未解析到。** PATH 无 `wind`、无 Wind 安装目录，
  所以所有运行都会落到退回档，此时「方法可靠性声明」必须写明实际档位与原因。
- **知识底座的原著原文不在仓内。** 51 源的 `fileRef` 一律不可解析（设计如此），
  只读得到内化摘要层。
- **没有语义检索，只有结构化检索。** 本体提供实体/关系与检索剖面，
  但不含向量检索。
- **平台私有校验器不在 CI 内。** `check-pack` 的 3/4/5/6 项检查依赖
  `@zhijian/dsh-expert-library`，CI 里不可得，会以 skip note 声明后跳过，
  其余检查照跑。
