# 路线图 / Roadmap

按「先补最会咬人的缺口」排，不按实现难度排。
每条都写明**为什么现在做**与**做完怎么验**。

## 近期（下一两个版本）

### 1. 闸门 C 的可执行部分
**为什么**：闸门 C 目前是 semantic，靠 `data_qc_out.json` 自证；而「数据陈旧」和「复权口径漂移」
是实测中最容易静默破的两件事——**静默陈旧比缺数据更危险**（缺数据会报错，陈旧只会给出错的数）。

**做什么**：
- 新增一个数据质检自检脚本（计划名 `check-data-quality`，**尚未实现**）：
  读 `data_qc_out.json`，机检三件套的证据齐备性
  （断点检测结论非空、复权口径有声明、跨源对账有两方数值且差异有上限）
- 新增一个规则版本自检脚本（计划名 `check-rule-version`，**尚未实现**）：
  读 `attribution_ledger.json`，机检每条记录带 `skill_version`，
  且跨版本累计命中率存在分组呈现

**怎么验**：各配一组注入式负向对照（沿用 `selftest-gates.mjs` 的形式），
并把 `wiring` 从 `semantic` 改为 `policy`（消费 N 键，键名须在执行器源码里按独立标识符出现）。

### 2. A 股本地波动率基准表
**为什么**：⑮ 层现在只能用海外参数，而 A 股涨跌停、T+1、停牌结构性改变波动率持续性。
不建本地表，「条件波动率」这一层在 A 股上就是照搬。

**做什么**：用中证官网一手面板（2015 起，20 个行业）自算各行业条件波动率，
产出 GARCH 参数与半衰期的本地估计，登记为新源并同步禁例词干。

**怎么验**：本表进入 `source/SOURCE-MANIFEST.json` 后，`banned-tokens-gap` 仍须为 0；
参数表进 `knowledge/experts/` 并声明 `distributable: false` 或改写为摘要层。

### 3. 命中率账本的对照基准
**为什么**：目前累计命中率没有无条件基准率，读者无法判断「60% 命中率」是本事还是基准。
**技能 vs 运气的二项检验要 ≥10 年样本**，现在远不到，所以更要把口径钉死。

**做什么**：账本每次登记时**自动附**无条件基准率与恒定基准两条对照线；
跨 `skill_version` 一律分组呈现，UI 上物理隔开，不允许直接加总。

**怎么验**：`check-rule-version.mjs` 断言账本里存在基准对照行；
不附基准的记录判为不合格（不是 note）。

## 中期

### 4. 语义检索
**为什么**：本体有 35 实体 33 关系，都是显式关系；「哪些层共同处理了某类问题」这类跨层提问
现在只能靠人读结构。

**做什么**：在本体上加一层向量索引（随包发布摘要层的嵌入，不含原文）。

**怎么验**：检索结果必须同时返回命中的实体 id 与关系边，否则不算命中——
避免「语义相近但结构无关」的假命中。

### 5. 冲突检测（口径矛盾对撞）
**为什么**：同一个量在两处用了不同口径，是最难在人工复核里发现的一类缺陷。

**做什么**：把已声明的 `caliberDeclarations` 变成可机检的同名量口径一致性检查；
发现不一致时像「数字三处对撞」一样给出具体位置。

**怎么验**：配负向对照（故意让两处口径不同，断言被抓住）。

### 6. 交付级门禁的离线化
**为什么**：现在 `audit-delivery.sh` 要 playwright 与联网字体环境，本地跑一次成本不低。

**做什么**：渲染产物检查拆成「必须联网」与「可离线」两档，CI 只跑必须联网那档，
本地默认跑离线档。

**怎么验**：两档的结果对同一份产物必须一致（除字体相关项）。

## 远期

### 7. 更多场景
目前两个场景（A 股观点看板、周期定位与配置研判）都是「产出研判」。
可加的是**回测场景**——但要小心：回测天然带前视偏差与参数选择偏差，
必须与闸门 A 的多重检验纪律配套，否则加场景就是加风险。

### 8. 多市场口径
当前一切以沪深300（价格指数口径）为基准、A股涨跌停与 T+1 为约束。
扩到港股或美股时，**基准、口径、成交机制都要重新声明**，
不是把参数换一下——这一点在设计上必须由第 0 层（总开关）强制。

## 明确不做

| 不做 | 理由 |
|---|---|
| 打包原著原文进仓 | 版权归原作者与出版方；边界一旦破，后果不可逆 |
| 让「语义检索」替代本体关系 | 语义相似不等于结构相关，会引入假命中；两者互补，不互相替代 |
| 把闸门判据从 semantic 改成 deterministic 而不补执行器 | 那只是把「我不确定」包装成「我确定」 |
| 跨版本直接加总命中率 | 会让规则变更伪装成能力提升——这正是闸门 C 第 2 条要防的 |
| 让模型自由发挥补齐框架外的机制 | 51 源的边界是资产也是责任；框架外的东西要写进框架，改版本号 |
