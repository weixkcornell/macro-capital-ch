# 样例：三道闸门怎么判（判定演练）

**这是判定逻辑的演练，不含任何真实数据或真实结论。**

对应定义：`method-packs/tri-gates.json`（判据全文）+
`quality-policies/baseline.json`（可机检配置）

## 为什么单独演示

因为「三道闸门」是这套方法里最容易被当成形式的部分。
下面三组条件会显示：**闸门不是「检查一下」，而是会直接否掉结论的**。

---

## 闸门 A · 统计可信（七条）

它管的是「这个数字可不可信」。

| # | 判据 | 典型触发 |
|---|---|---|
| 1 | t 阈值分档 | 样本越少，门槛越高；少于 30 个观测不单独下结论 |
| 2 | 多重检验校正 | 试了 7 个假设、只有 1 个显著 ⇒ 校正后存活 0 ⇒ 全部否掉 |
| 3 | Haircut / Deflated Sharpe | 算术口径须扣方差/2；**A 股禁沿用海外 2% 锚** |
| 4 | 正反双校准（因子双锚） | 发表偏误只需收缩 10–15% ⇒ 正锚；发表后衰减 50%+、拥挤与状态依赖侵蚀 ⇒ 反锚。**两侧须同时报，缺一失真** |
| 5 | 主动管理三判据 | 零和 + 平均无 α + 持续性弱 ⇒ 默认低费率指数/指增 |
| 6 | 收益口径折减 | 见第 3 条 |
| 7 | p-hacking 拦截 | 须披露调参次数与阈值档位 |

### 演练 ①：单个显著 ≠ 可用

**条件**：7 个假设里 1 个显著（p < 0.05），其余不显著。

**闸门 A 判定**：BH-FDR 与 Bonferroni 校正后**存活 0** ⇒ **不通过**。

**为什么**：单看会以为「有一个发现」；校正后存活 0 意味着
这 7 个假设里**没有任何一个**能扛住「你试了 7 次」这件事。
**未过校正 ≠ 反向信号成立**——这是第 4 条的红线。

---

## 闸门 B · 实施成本与可执行（六条）

它管的是「扣掉摩擦还值不值」。

核心公式：

```
净预期主动收益 = E[R_A] − 实施成本
```

**净额 ≤ 0 ⇒ 不发布任何超配/低配/轮动结论。**

### 演练 ②：正 alpha 但扣不到

**条件**：E[R_A] = +120 bp/年；实施成本五度量法可算得 4/5 项，合计 145 bp/年。

**闸门 B 判定**：净额 = 120 − 145 = **−25 bp/年 ≤ 0** ⇒ **不通过，不发布**。

**注意**：这里**不是**「结论打折后发布」，而是**不发布**。
成本吃掉的部分不会因为你把仓位调小就回来——小仓位的单位成本更高。

**另一个常见触发**：含杠杆的结论须声明自身杠杆上限（κ 取 2–3），
以及「正确但被强平」的风险与缓冲额度。**崩盘识别用杠杆水位，而非价格跌幅。**

---

## 闸门 C · 数据质量与规则版本（四条）

它管的是「输入数据对不对、规则稳不稳」。

闸门 A 与 B **都默认**输入数据是对的、规则是稳定的。
但实测中这两件事都会破：单一厂商接口的分位与自算分位会背离、
序列会停在 2016/2021 年仍返回数据、复权口径会随数据源改变、
规则会在版本演进中静默变更。

| # | 判据 | 不过怎么办 |
|---|---|---|
| 1 | **数据质检三件套**：断点检测（水平跳变 + 尾部停滞，**静默陈旧比缺数据更危险**）、复权校验（前复权/后复权/不复权口径跨期不得改变）、跨源对账（**只用单一厂商接口分位而不做对账 = 未通过本条**） | 该数据不得进入正文 |
| 2 | **规则版本绑定**：每次规则变更须在 CHANGELOG 留痕，当期看板单列「本期规则变更」；无变更也须写「本期无规则变更」，**禁止静默变更**。账本每条带 `skill_version`，**跨版本累计命中率必须分组呈现**，不得跨版本直接加总期数 | 当期须补登 CHANGELOG 并说明影响范围 |
| 3 | **命中率账本的对照与自评约束**：须附无条件基准率 + 恒定基准，无对照的累计命中率不得进正文；「部分验证」类模糊判定须给操作化规则，给不出规则的记 `indeterminate` 并**排除在分母之外**；判定标准须事前登记 | 累计命中率不得展示 |
| 4 | **口径快照**：同表同类同日，跨源拼装须显式声明且不得用于精度要求高的结论 | 该表不得用于精度要求高的结论 |

### 演练 ③：数据是旧的，但接口没报错

**条件**：某行业指数的分位序列，接口正常返回、无错误码，但序列末端停在 2021 年。

**闸门 C 判定**：断点检测发现**尾部停滞** ⇒ 该数据**不得进入正文**。

**这是最危险的一类失败**：缺数据会报错，**陈旧数据不会**——
它会安静地给出一个错得很自信的数。
所以质检三件套里的「尾部停滞」与「水平跳变」同等重要。

### 演练 ④：换了规则但没说

**条件**：v2.8 的账本累计命中率 58%，v2.9 改了评分规则，续算后显示 63%。

**闸门 C 判定**：跨版本未分组 ⇒ **累计命中率不得展示**。

**为什么**：63% 里有多少来自能力、多少来自规则放松，**不分组就分不出来**。
这正是「规则静默变更」最隐蔽的危害——它会伪装成能力提升。

---

## 三道闸门怎么合起来看

| 情形 | A | B | C | 结果 |
|---|---|---|---|---|
| ① 单个显著，校正后存活 0 | ✗ | — | — | **不发布**（且不得反向解读） |
| ② 正 alpha，成本吃掉 | ✓ | ✗ | — | **不发布**（净额 ≤ 0） |
| ③ 数据陈旧 | — | — | ✗ | **该数据不进正文** |
| ④ 跨版本累计命中率 | — | — | ✗ | **累计命中率不得展示** |
| 全过 | ✓ | ✓ | ✓ | 可发布，**仍须过末位文风渲染** |

**「可发布」也不是终点**：文风渲染是末位工序，事实层冻结，
出 `style-report.json`（反例命中数须 0、刊名出现次数须 0），缺报告视同未渲染。

## 一句话记住三者的分工

- **闸门 A**：这个数字**可不可信**？
- **闸门 B**：扣掉摩擦**值不值**？
- **闸门 C**：输入的数据**对不对、规则**稳不稳**？

**A 与 B 管观点，C 管长期可信度**——C 不产出观点，但它决定半年后这套东西还值不值得看。
